# Проверка ресурсов браузерного мира

Это отдельный тестовый контейнер с настоящими Campaign, CampaignShowcase и World. Он загружает локальные GLTF, текстуры, анимации и WebGL renderer, затем проходит лес, двор и крыши, собор и крипту шесть раз. Используется обычный игровой ввод с физикой 120 Гц. Первый маршрут прогревает ресурсы.

Запуск из корня репозитория:

```console
node scripts/performance/run-docker.mjs
```

При изменении исходников используйте полный запуск с построением образа. Для повторного запуска уже построенного, неизменённого образа:

```console
node scripts/performance/run-docker.mjs --skip-build
```

Образ называется `new0-browser-resources:pw-1.64.1`, контейнер получает отдельное имя `new0-resources-...`. Команда сохраняет результаты в `scripts/performance/results/<идентификатор>/` и удаляет только созданный ею контейнер. Файл `results/latest-run.json` указывает на последний каталог.

Ограничения тестового запуска: один CPU, 1536 MiB памяти, отключённый swap, 512 MiB собственной общей памяти, 256 процессов и сетевой режим `none`. Статический сервер и Chromium общаются через loopback внутри контейнера. В отчёте сохранены фактические ограничения cgroup и Docker, а также пиковая память контейнера.

В тесте используется viewport 270×180 и программный рендерер SwiftShader. Соотношение сторон 3:2 сохраняет охват камеры. Небольшое разрешение ограничивает затраты растеризации на одном CPU и позволяет завершить шесть маршрутов за срок CI. Проверка ресурсов не оценивает качество изображения или FPS. Пакет `@playwright/test` и официальный образ Playwright закреплены на 1.64.1. Образ дополнительно закреплён по digest `sha256:2f05f8a734509a7b3f26a912639488ee08f58a7b292d14d62271bcff9038768f`. Версия и digest проверены 16 ноября 2026 года через официальный MCR registry и npm registry.

Быстрый режим продвигает симуляцию на величину до 12 секунд за отрисованный кадр, сохраняя шаг ввода 1/120 секунды. Кадр заканчивается раньше при смене локации, оружия, брони, осмотра, лечения, дверей, сундуков, мимика, смерти, дропа или выбранных световых якорей и их диапазонов. Короткие переходы атаки, замаха и отдачи не создают дополнительных кадров. Промежуточные визуальные позы и короткие эффекты могут быть пропущены. В отчёте указаны фактические секунды симуляции и число отрисованных кадров каждого маршрута. Это нагрузка для проверки выделения и удержания ресурсов. Его показатели времени кадра нельзя использовать для оценки FPS телефона или качества анимации. Проверка не включает HUD, аудио и дополнительный слой soft-light основной страницы.

Тест завершается ошибкой, если хотя бы одно из шести прохождений не закончило все четыре зоны, не отрисовало какую-либо зону, использовало диагностическое упрощение или изменило настройки. После прогрева числа геометрий, текстур, программ и моделей должны совпадать во всех повторах 2–6. Ошибки JavaScript, необработанные Promise rejection, ошибки загрузки ресурсов, падение страницы и потеря WebGL-контекста также означают ошибку теста. Отменённые Chromium fetch-потоки с ERR_ABORTED записаны отдельно. Успешная загрузка World и завершение всех зон остаются обязательными.

Если браузер предоставляет heap API и принудительную сборку мусора, проверяется heap после GC. Сигнал удержания памяти: рост между повторами 2 и 6 больше 8 MB или разброс больше 12 MB. При отсутствии API отчёт прямо указывает, что такой проверки не было. Стабильные счётчики Three.js сами по себе не исключают утечку JavaScript, драйвера или памяти GPU.

Основные файлы результатов:

- `world-resources.json`: шесть маршрутов, стадии, счётчики Three.js, heap при наличии API, версии клиента и ассетов.
- `validation.json`: итог строгой проверки и причины отказа.
- `container-resources.json`: ограничения, периодические измерения памяти cgroup, пик и события OOM.
- `container-state.json` и `docker-limits.json`: состояние и фактическая конфигурация контейнера.
- `completed-soak.jpg`, `runner.json` и журналы: контекст выполненного теста.

Сохранённый отчёт можно повторно проверить без браузера:

```console
node scripts/performance/validate-soak.mjs scripts/performance/results/<идентификатор>/world-resources.json
```

Для визуального исследования в уже запущенном локальном Vite доступна страница `/scripts/performance/fixtures/world-lab.html`. Кнопка «Один полный прогон» устанавливает обычную скорость. Флажок «Прежний радиус актёров» отключает только проверку actorFrustum в этой лабораторной обёртке, оставляя прежний радиус по Z. Это позволяет сравнить два режима в одной сборке. Поле `previous_actor_radius` сохраняется вместе с `asset_revision`, `client_revision` и `fixture_revision`. Строгий шестикратный resource-soak требует выключенных диагностических флажков.

Workflow `.github/workflows/browser-resources.yml` запускает ту же команду для затронутых PR и вручную через workflow_dispatch. Ожидание шести маршрутов ограничено восемнадцатью минутами, включая более медленный программный рендеринг. Он сохраняет артефакты даже после неуспешного прогона. Локальная проверка не подтверждает выполнение GitHub Actions, а Linux SwiftShader не подтверждает 60 FPS на iPhone.

Первичные источники:

- [Официальная документация Playwright для Docker](https://playwright.dev/docs/docker) описывает образ с браузерами и необходимость установить совпадающий пакет отдельно.
- [Официальная конфигурация Playwright Test](https://playwright.dev/docs/test-configuration) описывает один worker, таймауты и локальный webServer.
- [Ограничения ресурсов Docker](https://docs.docker.com/engine/containers/resource_constraints/) описывают hard memory limit, CPU quota и swap.
- [Проверенный manifest MCR](https://mcr.microsoft.com/v2/playwright/manifests/v1.64.1-noble) и [пакет npm 1.64.1](https://registry.npmjs.org/@playwright/test/1.64.1) задают воспроизводимые версии тестовой среды.

Для короткого диагностического запуска можно задать `NEW0_RESOURCE_WAIT_MS=60000` перед командой. Он по-прежнему запрашивает шесть прохождений и завершится ошибкой, если срока недостаточно. Частичный отчёт сохраняет уже завершённые повторы и текущее положение маршрута. Это не успешный ресурсный прогон.
