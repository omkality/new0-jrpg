# Подготовка боевых анимаций

Локальные инструменты для воспроизводимой сборки анимационных GLB. Они не входят
в runtime игры и не меняют `src/` или исходные модели персонажей.

Нужен Node.js 24+ и модели из текущего репозитория:

- `public/assets/knight/knight.glb`
- `public/assets/cast/prisoner.glb`
- `public/assets/cast/gaoler.glb`

```powershell
cd scripts/assets
npm ci
npm run build
```

Зависимости закреплены в `package-lock.json`: glTF Transform 4.5.1 и Three.js
0.187.0. Все пути вычисляются относительно расположения скриптов, рабочая
директория и путь к проекту на конкретной машине не зашиты в код.

## Что выполняется

1. `author-combat.mjs` загружает исходный риг и reference Idle. Параметры поз
   берутся из `combat-poses.mjs`. FK и двухзвенный IK рук/ног вычисляются на каждом
   экспортируемом timestamp. Используются непрерывные Hermite-кривые целей,
   статические опорные точки стоп и проверка фактической weighted-поверхности.
2. `retarget-combat.mjs` переносит движение на prisoner и gaoler через native Idle,
   world-space rotation delta и IK с длинами конечностей конкретной модели.
   Хват правой руки пересобирается под соглашение о направлении клинка.
3. `validate-combat.mjs` читает готовые файлы, проверяет структуру, тайминги,
   нормализацию кватернионов, непрерывность поз в стыках комбо и положение поверхности
   относительно пола. Он также проверяет сохранность Death.

Результаты:

- `public/assets/motion/combat.glb`
- `public/assets/motion/prisoner-combat.glb`, также подходит watcher
- `public/assets/motion/gaoler-combat.glb`
- `public/assets/motion/source-rest.json`
- `public/assets/motion/contract.json`

Численные отчёты сохраняются в игнорируемом `work/asset-authoring/`.

## Контракт с игровым кодом

| Клип    | Полная длительность | Контакт | Переход к следующему удару |
| ------- | ------------------: | ------: | -------------------------: |
| Attack1 |              0,74 с |  0,30 с |                     0,52 с |
| Attack2 |              0,70 с |  0,27 с |                     0,51 с |
| Attack3 |              1,00 с |  0,42 с |         Завершение цепочки |

Attack2 в нуле продолжает позу Attack1 в 0,52 с. Attack3 в нуле продолжает
Attack2 в 0,51 с. В эти моменты тело и оружие остаются в follow-through,
возврата в Guard между звеньями нет. Одиночный или двойной удар доигрывает свою
ветку восстановления до полной длительности. Gameplay отвечает за окна ввода,
расход выносливости, попадание и запрет блока во время цепочки и восстановления.

Основная сетка экспорта составляет 60 Гц. В файл также входят точные моменты
контакта, перехода и соседние точки для сохранения направления скорости в стыке.
Рендер не зависит от числа ключей в клипе.

Оружие прикрепляется к `hand_R`, grip `(0, 0.06, 0)`, клинок направлен по
локальной `-Z`. Меч, построенный вдоль `+Y`, поворачивается на `X = -PI/2`.
Уклонения in-place, перемещение выполняет контроллер игры.

## Сохранённое падение

В `seeds/` хранятся три клипа Death предыдущей демки. Сборка копирует их значения
каналов без пересчёта. `animationDigest` сверяет target/path, timestamp и сырые
float-массивы. Это сохраняет одобренную постановку падения при изменении остальных
движений. `capture-death-seeds.mjs` предназначен только для отдельного обновления
исходных seeds после согласованной правки Death.

## Границы проверки

Численное совпадение поз на стыке не является оценкой художественного качества.
Нужно смотреть в игре силуэт замаха, хват, расстояние оружия до тела, контакт стоп,
камеру и смешивание с locomotion. Линейная интерполяция glTF и пропорции разных
персонажей оставляют небольшие различия мгновенной скорости между ключами.

Источник ригов Patch CC0, включая раскрытое AI-происхождение базовых моделей и
reference Idle, описан в `public/assets/knight/SOURCES.md` и
`public/assets/cast/SOURCES.md`. Новые боевые кривые созданы для этого проекта,
данные движения из чужих игр не используются.
